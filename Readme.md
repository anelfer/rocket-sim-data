# Rocket Telemetry Simulator

[![Telegram](https://img.shields.io/badge/Author-Telegram-blue?logo=telegram)](https://t.me/anelfer)

_Version 1.12.2_

Симулятор запуска двухступенчатого носителя и его жидкостных ракетных двигателей.
Состояние ракеты — вектор положения и скорости в инерциальной геоцентрической
системе; высота, скорости, наклонение и элементы орбиты выводятся из него, а не
хранятся отдельно. Двигатель считается не коэффициентом тяги, а по физике:
баланс мощности турбонасоса, запирание горловины, перепад на форсунках,
охлаждение стенки.

Всё это можно ломать руками во время полёта и смотреть, что произойдёт.

## Запуск в Docker

Поднимаются три службы: симулятор, Prometheus и Grafana с готовыми дашбордами.

```bash
# Собрать и поднять всё
docker compose up -d --build

# Убедиться, что поднялось
docker compose ps

# Смотреть журнал симулятора
docker compose logs -f rocket-simulator

# Запустить полёт
curl -X POST http://localhost:8087/api/sim/start

# Остановить полёт, не гася контейнеры
curl -X POST http://localhost:8087/api/sim/stop
```

Полезные команды на каждый день:

```bash
# Пересобрать только симулятор после правки кода
docker compose up -d --build rocket-simulator

# Перечитать дашборды Grafana после правки json
docker compose restart grafana

# Погасить всё, сохранив накопленные метрики
docker compose down

# Погасить и стереть историю Prometheus и настройки Grafana
docker compose down -v

# Ускорить время в пять раз
curl -X POST "http://localhost:8087/api/sim/speed?value=5"

# Выбрать носитель перед запуском
curl -X POST http://localhost:8087/api/profiles/select \
     -H 'Content-Type: application/json' -d '{"id":"starship"}'
```

Без Docker:

```bash
go run ./cmd
```

## Куда заходить и под какими учётками

| Что | Адрес | Учётка |
|---|---|---|
| **Пульт управления** — основной интерфейс | http://localhost:8087 | не требуется |
| **Grafana** — дашборды телеметрии | http://localhost:3000 | `admin` / `admin` |
| Дашборд «Параметры полёта» | http://localhost:3000/d/rocket-telemetry | входит по той же учётке |
| Дашборд «Двигательная установка» | http://localhost:3000/d/rocket-propulsion | входит по той же учётке |
| **Prometheus** — сырые метрики и запросы | http://localhost:9090 | не требуется |
| Метрики симулятора | http://localhost:8086/actuator/prometheus | не требуется |

Grafana при первом входе попросит сменить пароль — можно пропустить. Анонимный
просмотр включён, поэтому дашборды открываются и без входа, но с правом только
смотреть; чтобы править панели, нужно войти под `admin`.

Пароль задаётся в `docker-compose.yml` переменными `GF_SECURITY_ADMIN_USER`
и `GF_SECURITY_ADMIN_PASSWORD`. После смены пароля в веб-интерфейсе Grafana
переменные перестают действовать — она хранит его в своём томе.

## Что можно менять на сайте

Пульт открывается по адресу http://localhost:8087 и состоит из трёх панелей.

### Слева — воздействия

Свыше полусотни параметров, разложенных по подсистемам:

| Вкладка | Что меняется |
|---|---|
| **Турбонасос** | обороты вала, напор и КПД насосов, отбор на турбину, охлаждение подшипников, дисбаланс ротора, газ на входе |
| **Клапаны** | положение и скорость приводов горючего, окислителя, газогенератора, задержка отклика |
| **Баки** | давление наддува, расход и клапан наддува, утечки, засорение и разрыв магистрали, раскачка жидкости |
| **Камера** | полнота сгорания, соотношение компонентов, площади форсунок, запас устойчивости, пульсации |
| **Сопло** | расход и проводимость охлаждения, локальный перегрев, скорость эрозии горловины |
| **Двигатель** | дроссель, шум и отказы датчиков |
| **Рулевой тракт** | ход и скорость привода, смещение, полоса и демпфирование автопилота, момент двигателей ориентации |

Каждый параметр меняется в одном из режимов: разовая установка, ступенька,
плавный переход за заданное время, доля от номинала, временное воздействие
с возвратом, отказ (заклинило, обесточено, замерло, врёт датчик, разрыв).
Рядом с каждым параметром написано, что произойдёт и на что это повлияет.

Команды можно адресовать **одному двигателю** — выберите его в полосе двигателей
или щёлкните по соплу на развёртке. Остальные продолжат работать штатно.

### В центре — состояние

- Полоса всех двигателей ступени: обороты, тяга, давление в камере, состояние
  агрегата. Отказ одного виден на фоне остальных.
- Панель эксперимента с турбонасосом и быстрыми кнопками отказов.
- Трёхмерная ориентация корпуса: тангаж, рыскание, крен, угол атаки, вектор потока.
- Ключевые показатели и предупреждения.
- **Отклик модели на воздействие** — величины, которые действительно изменились,
  с временем начала реакции. Интерфейс не утверждает связь, которую модель
  не подтвердила измерением.

### Справа — данные

| Вкладка | Что даёт |
|---|---|
| **Графики** | до полутора десятков величин с отметками вмешательств |
| **Развёртка** | чертёж носителя в масштабе: уровни в баках падают по телеметрии, сопла в разрезе, вид с торца по любой ступени, качание камер, выноски с массой и давлением. Чертёж подгоняется под высоту панели, масштаб от 60 до 300 %. Ползунок на баках задаёт заправку ступени — она применится со следующего пуска и изменит стартовую массу, тяговооружённость и дальность |
| **Вход в атмосферу** | вид корабля сбоку с фактическими углами плавников, подсветка нагрева наветренной стороны, ползунок на каждый привод. Кнопка «Сход с орбиты» разворачивает корабль против движения и выдаёт тормозной импульс |
| **Сравнение** | текущий прогон против сохранённого эталона |
| **Журнал** | все команды с ответом модели, с экспортом |
| **Сценарии** | последовательности воздействий по времени, с сохранением и импортом |
| **Grafana** | дашборды прямо в пульте |

### Сверху — ход прогона

Выбор носителя, старт и остановка, пауза, шаг, скорость времени от 0.1× до 10×,
сброс, аварийное выключение, возврат в штатный режим.

Два переключателя снимают ограничения:

- **Небезопасный режим** — разрешает выходить за паспортные пределы параметра.
- **Прямое управление** — снимает подтверждения критических команд.

## Носители

Профиль выбирается в верхней панели и применяется при следующем запуске: от него
зависят массы, геометрия, состав двигательной установки и точка старта.

| | Falcon 9 Block 5 | Starship / Super Heavy (V3) |
|---|---|---|
| Двигателей | 9 + 1 | 33 + 6 |
| Топливо | РГ-1 / жидкий кислород | жидкий метан / жидкий кислород |
| Схема двигателя | открытая, с газогенератором | замкнутая, полнопоточная |
| Давление в камере | 9.7 МПа | 35 МПа |
| Стартовая масса | 562 т | 5375 т |
| Тяга у земли | 7.6 МН | 79.7 МН |
| Полезная нагрузка | 12 т | 100 т |

Параметры Starship соответствуют третьему блоку 2026 года. Открытые источники
расходятся между собой — стартовую массу называют от 5250 до 5375 т, суммарную
тягу от 80.8 до 90.6 МН, — поэтому взят внутренне согласованный набор: тяга
и удельный импульс считаются моделью из давления, геометрии сопла и расхода,
а не задаются отдельным числом. На установившемся режиме модель даёт 34.9 МПа
в камере, 800 кг/с расхода и 2.56 МН у земли на двигатель — то есть 79.7 МН
на старте против публикуемых 80.8 МН.

Что упрощено, перечислено в самом профиле и показывается при его выборе:
возврат ступеней не моделируется, программа тангажа задана таблицей, а вместо
двух дожигательных газогенераторов работает один турбонасосный агрегат.

## Устройство проекта

```
cmd/                REST API, WebSocket, веб-пульт (вшит в бинарник)
  web/              исходники интерфейса: index.html, app.js, style.css
control/            слой воздействий: реестр параметров, команды, причинный анализ
metrics/            публикация в Prometheus
simulator/          интегратор, фазы полёта, двигательная установка, телеметрия
  vehicle/          конфигурации носителей, каталог профилей, обводы для развёртки
  env/              ветер, отработавшая ступень, поле обломков
  physics/          константы, векторы, кватернионы, гравитация, атмосфера, нагрев
  orbit/            наведение, фазы полёта, ПИД-регуляторы
  propulsion/       баки, турбонасосы, камеры, сопла, датчики
grafana/            дашборды и провижининг
prometheus/         конфигурация сбора метрик
tools/              генератор дашбордов и приёмочный сценарий
```

Тесты лежат рядом с кодом, который проверяют, — так устроен Go: тест в отдельной
папке теряет доступ к внутренностям пакета, а большинство здешних проверок
работают именно с ними. Поэтому порядок наводится не выносом тестов, а делением
на пакеты: тесты расходятся по папкам следом за своим кодом. Внутри пакета файлы
названы по теме — `integrator_test.go`, `thermal_test.go`, `spent_stage_test.go`,
`campaign_test.go`, — а не свалены в один `simulator_test.go`.

## Физическая модель

**Силы.** Гравитация с поправкой J2, дающей реальную прецессию узлов. Тяга,
направленная ориентацией корпуса. Сопротивление, считаемое по скорости
относительно вращающейся вместе с Землёй атмосферы.

**Атмосфера.** USSA-76 до 100 км, стандартная термосфера и экзосфера до 1000 км,
плотность интерполируется логарифмически.

**Нагрев корпуса.** Температура торможения, конвективный поток по
Саттону–Грейвсу, радиационное равновесие в вакууме.

**Охлаждение камеры.** Обе стороны стенки считаются по критериальным
зависимостям, а не задаются числом.

Со стороны газа — соотношение Бартца: `Nu = 0.026·Re^0.8·Pr^0.4`, приложенное
к течению в сопле. Горловина заперта, поэтому массовый поток через неё равен
`p_к/c*`, и отсюда знаменитое `h ∝ p^0.8` — показатель приходит из числа
Рейнольдса, а не подобран. Поток в стенку считается как `h·(T_восст − T_стенки)`,
то есть раскалившаяся стенка принимает меньше тепла.

Со стороны охладителя — Дитус–Бёльтер по фактическому числу Рейнольдса
в канале: `Nu = 0.023·Re^0.8·Pr^0.4`. Проводимость участка следует из числа
каналов, их сечения, толщины и теплопроводности огневой стенки — то есть
из конструкции, а не из коэффициента. Падение расхода само роняет теплоотдачу,
потому что падает число Рейнольдса.

Температура стенки получается из баланса энергии узла:
`C·dT/dt = h_газ·A·(T_восст − T) − U_охл·A·(T − T_охл)`.

На номинале это даёт для керосинового двигателя поток 33 МВт/м² в горловине
при стенке 822 К и скорости керосина в канале 94 м/с, для метанового
на 350 бар — 121 МВт/м² при стенке 850 К и скорости метана 273 м/с. Порядки
совпадают с опубликованными для этих двигателей.

**Управляющие поверхности.** Плавники корабля и решётчатые рули ступени
считаются по ньютоновской теории обтекания: `Cp = 2·sin²θ` по местному углу
панели к потоку, сила по нормали, момент — на плече от центра масс. Ниже
третьего числа Маха добавляется линейный по углу член: там панель работает
как обычное оперение. Власть этого органа определяется скоростным напором,
поэтому в разрежённых слоях перекладка плавников почти ничего не даёт,
а в плотных они сильнее любого другого органа управления.

**Вход в атмосферу.** Корабль возвращается брюхом вперёд под углом атаки
около семидесяти градусов. Сопротивление раскладывается на продольное
и поперечное: вдоль корпуса работает обтекаемая форма, поперёк — цилиндр
с коэффициентом около полутора и площадью борта в семь раз больше миделя.
Именно на этом держится торможение: скорость гасится с первой космической
до восьмисот метров в секунду к двадцати километрам, наибольший напор около
сорока килопаскалей, поток в критической точке до 1.2 МВт/м². Угол атаки
держат четыре плавника; каждый можно взять в ручное управление на пульте.

**Расходование компонентов.** Соотношение в камере зависит от давлений подачи
и по ходу работы ступени плывёт, поэтому баки не пустеют одновременно сами
по себе. Как и на настоящей ступени, за этим следит система управления
расходованием: она сравнивает остатки и подтравливает клапан горючего
с властью в десять процентов. Без неё у Starship окислитель кончался, когда
в баке оставалось двадцать восемь тонн метана.

**Прогар.** Перегрев стенки имеет последствия, а не только цвет строки
в предупреждениях. Выше предела материала копится повреждение — квадратично
по перегреву: сотня градусов сверх предела даёт полторы минуты, три сотни —
восемь секунд. При полном повреждении стенка прогорает, двигатель гаснет
и больше не запускается.

**Двигатель.** Давление в камере находится совместным решением условия запирания
горловины `p_к = ṁ·c*/A_гор` и перепада на форсунках `ṁ = Cd·A·√(2ρΔp)`. Обороты
вала — из баланса мощности `I·ω·dω/dt = P_турб − P_насос − P_потерь`. Регулятор
держит обороты через клапан газогенератора, а не записывает их напрямую.

**Угловое движение.** Уравнения Эйлера для твёрдого тела: аэродинамический
момент, демпфирование, управляющий момент от качания камер, ограничение
по располагаемому моменту. Ошибка ориентации считается через кватернион,
поэтому вертикальный участок не даёт вырождения.

**Интегрирование.** Рунге–Кутта четвёртого порядка с единым шагом, независимым
от интервала публикации телеметрии.

## Параметры модели и степень их реалистичности

Ниже — всё, что модель действительно **считает**, а не просто показывает в интерфейсе,
с честной оценкой по одной и той же шкале:

- **Точно** — точная физика, приближений нет (законы Ньютона, кватернионная кинематика,
  задача двух тел, точные геометрические соотношения).
- **Инженерно** — стандартное инженерное приближение, которым реально пользуются при
  эскизном проектировании (J2, USSA-76, Саттон-Грейвс, критерии Бартца и Дитуса-Бёльтера,
  ньютоновская теория гиперзвукового обтекания, ПИД-наведение).
- **Качественно** — верно воспроизводит поведение и порядок величины, но числа внутри
  подобраны, а не выведены (профиль ветра, пороги разрушения, кривая Cx(M)).
- **Заглушка** — есть в коде, но либо ни на что не влияет, либо не смоделировано вовсе.

### Орбитальная механика и системы координат

| Параметр | Как считается | Реалистичность |
|---|---|---|
| Гравитация | Ньютоновский член + возмущение J2 (реальные константы WGS-84), даёт настоящую прецессию узлов | Инженерно — J2 есть, старших гармоник, Луны и Солнца нет |
| Элементы орбиты | Точный аналитический вывод из вектора состояния: эксцентриситет, наклонение, восходящий узел, аргумент перицентра, включая вырожденные случаи (круговая, экваториальная, гиперболическая) | Точно — классическая задача двух тел |
| Период, скорость по vis-viva, скорость круговой орбиты | Точные формулы задачи двух тел | Точно |
| Азимут старта под заданное наклонение | `sin(A) = cos(i)/cos(φ)`, сферическая тригонометрия | Инженерно — без поправки на скорость вращения Земли; компенсируется отдельным контуром коррекции наклонения в наведении |
| Вращение Земли, ECI ↔ ECEF | Поворот вокруг оси Z на звёздные сутки | Инженерно — без прецессии, нутации, движения полюсов |
| Географические координаты | Сферическая модель Земли | Качественно — без сжатия эллипсоида WGS-84, ошибка широты до ≈0.19° |
| Векторы и кватернионы | Точная алгебра; ошибка ориентации — через кватернион, не углы Эйлера, поэтому вертикальный участок не вырождается | Точно |

### Атмосфера, аэродинамика, нагрев

| Параметр | Как считается | Реалистичность |
|---|---|---|
| Плотность, температура, давление атмосферы | Табличная US Standard Atmosphere 1976 до 100 км (лог-линейная интерполяция плотности), дальше — упрощённые термосфера и экзосфера | Инженерно до 100 км (сверено с эталоном, 1–10%); качественно выше — солнечной активности нет |
| Скоростной напор, скорость звука | `q = ½ρv²`, `a = √(γRT)` | Точно |
| Коэффициент сопротивления по числу Маха | Подобранная кривая для удлинённого тела вращения (пик у M ≈ 1.1) | Качественно — форма верная, числа не выведены под конкретный носитель |
| Разделение сопротивления на осевое и поперечное | Проекция площадей по углу атаки, разный Cx вдоль и поперёк потока | Качественно — без этого вход брюхом вперёд был бы неотличим от входа носом |
| Нагрев торможением | Саттон-Грейвс: `q = k·√(ρ/Rₙ)·V³` | Инженерно — та же методика, что и в реальном эскизном проектировании теплозащиты |
| Радиационное равновесие в вакууме | Баланс поглощения и излучения по Стефану-Больцману (метод α/ε) | Инженерно — доля освещённости и альбедо фиксированы, не считаются из геометрии орбиты |
| Ионизация и радиоблэкаут | Уравнение Саха для «воздуха» как одного эффективного вещества, порог по S-диапазону | Качественно — реальный воздух не одна субстанция с одной энергией ионизации |
| Плавники и решётчатые рули | Ньютоновская теория `Cp = 2·sin²θ` на гиперзвуке, ниже M=3 — линейная поправка | Инженерно — тот же метод, что и для реальных аппаратов на этапе эскизного проектирования |
| Геометрия плавников корабля | Азимуты и площади оценены по видеозаписям пусков (в коде так и написано: данных о ходе привода в открытом доступе нет) | Качественно, честно помечено как оценка |
| Аэродинамический момент и запас устойчивости | Момент от разноса центра давления и центра масс, демпфирование — от интегрирования локальной скорости по длине корпуса | Качественно — центр давления считается неподвижным (половина длины корпуса) |

### Двигательная установка

| Параметр | Как считается | Реалистичность |
|---|---|---|
| Давление в камере | Совместное решение запирания горловины `p = ṁ·c*/A` и перепада на форсунках `ṁ = Cd·A·√(2ρΔp)` | Инженерно — методика реального проектирования ЖРД |
| Обороты турбонасоса | Баланс мощности вала `I·ω·dω/dt = P_турб − P_насос − P_потерь`, обороты держит регулятор через клапан газогенератора | Инженерно |
| Тяга и удельный импульс | Изоэнтропический коэффициент тяги сопла, откалиброванный коэффициентом реальности (2D-потери, трение) под паспортные числа Raptor 3 и Raptor Vacuum (267/280 тс, 333.5/350 с; 255.2/295.9 тс, 318.8/369.7 с) | Инженерно — калибровка сходится с паспортными числами до второго знака |
| Охлаждение камеры, сторона газа | Критерий Бартца `Nu = 0.026·Re⁰·⁸·Pr⁰·⁴` | Инженерно — именованная методика, не подобранный коэффициент |
| Охлаждение камеры, сторона охладителя | Дитус-Бёльтер `Nu = 0.023·Re⁰·⁸·Pr⁰·⁴` по фактическому числу Рейнольдса в тракте | Инженерно |
| Прогар стенки | Квадратичное накопление повреждения выше предельной температуры | Качественно — реальная эрозия и абляция устроены сложнее |
| Неустойчивость горения (chug, акустика) | Частоты заданы, спектральный анализ давления в камере | Качественно — не решение уравнений устойчивости камеры сгорания |
| Кавитация насоса | Порог по запасу NPSH | Качественно |
| Плескание компонента в баке | Частота первой формы `ω² = 1.84·g/R·tanh(1.84·h/R)` — формула Абрамсона для цилиндрического бака | Инженерно — настоящая формула, не выдумана |
| Расходный бак (header tank) | Отдельная ёмкость под наддувом кормит посадочные двигатели независимо от ориентации основных баков | Инженерно — реальное решение Starship, не допущение модели |
| Диапазон дросселирования | 40–108 % для Raptor, эксплуатационный потолок 93.5 % (запас на форсирование при отказе двигателя) | Инженерно — соответствует публикуемым эксплуатационным пределам |
| Компенсация отказа двигателя | Оставшиеся форсируются пропорционально требуемой суммарной тяге | Качественно — верное поведение, не алгоритм настоящего бортового компьютера |
| Команда газа ниже аттестованного предела | Автоматика наведения предел держит; прямая команда оператора проходит как есть и может кончиться погасанием | Качественно |
| Шум датчиков двигателя | Настраиваемый множитель шума на канал | Качественно |

### Наведение и управление

| Параметр | Как считается | Реалистичность |
|---|---|---|
| Программа тангажа на разгоне | Вертикальный участок → фиксированный «кик» → таблица высота→угол, откалиброванная под тяговооружённость носителя среднего класса | Инженерно, разомкнутый контур — для Starship в коде прямо отмечено как неоптимальное (профиль подобран под Falcon 9) |
| Наведение второй ступени на разгоне | ПИД по апоцентру, затем переключение на ПИД по высоте/вертикальной скорости при подходе к цели | Качественно — верная идея (обратная связь по орбитальным элементам), не PEG и не оптимальное наведение настоящих бортовых компьютеров |
| Довыведение и циркуляризация | ПИД по поперечной скорости к круговой, длительность импульса — из тяги и уравнения Циолковского | Инженерно — использует настоящую орбитальную механику, не готовый ответ |
| Ограничение перегрузки | `maxThrottle = a_max·m/F` | Точно как формула; инженерно — один и тот же предел применяется ко всем фазам без разбора |
| Разгрузка по углу атаки (q·α) | Предел угла атаки уменьшается обратно пропорционально скоростному напору | Инженерно — тот же принцип, что и у настоящих носителей |
| Азимут и его коррекция по наклонению | Базовый азимут + ПИД по измеренному наклонению | Качественно — упрощение базовой формулы компенсируется обратной связью |
| ПИД-регулятор | Дискретный ПИД с anti-windup и защитой от «удара» по производной на первом шаге | Инженерно — коэффициенты контуров подобраны вручную, не выведены из модели объекта управления |
| Порог `AtmosphericQThreshold` | Задокументирован как переключатель режима наведения по скоростному напору | Заглушка — нигде в коде не читается, ни на что не влияет |

### Корпус, ориентация, вход в атмосферу

| Параметр | Как считается | Реалистичность |
|---|---|---|
| Интегрирование движения | Рунге-Кутта 4 порядка, фиксированный шаг | Инженерно |
| Вращательная динамика | Точные уравнения Эйлера твёрдого тела с гироскопическим членом | Точно как уравнение; инженерно — тензор инерции как у однородного цилиндра, не как у реального распределения масс |
| Автопилот ориентации | ПД по требуемому угловому ускорению → момент → угол качания камеры; не зависит от массы и тяги ступени | Инженерно |
| Привод качания камеры | Ограничение по скорости и ходу (5°, 10°/с) | Инженерно |
| Двигатели ориентации (РСУ) | Постоянный момент с мёртвой зоной, добирают только то, чего не хватает от плавников и качания камер | Качественно — без реального расхода топлива и цикла импульсов |
| Вход в атмосферу брюхом | Угол атаки интерполируется от 70° (гиперзвук) до 90° (дозвук) по числу Маха | Качественно — верный тренд, но по подобранной, не оптимальной по аэродинамическому качеству траектории |
| Манёвр разворота и посадочный импульс | Высота начала разворота и включения двигателей вычисляется из скорости снижения и располагаемой тяги, а не задаётся числом | Инженерно |
| Оценка посадки | Жёсткая посадка при снижении быстрее 6 м/с или крене больше 15° | Качественно — порог правдоподобный, не расчёт устойчивости по опоре ног |
| Заваливание после жёсткой посадки | Кинематическое падение с постоянной угловой скоростью | Качественно — не через момент от смещения центра масс |

### Теплозащита

| Параметр | Как считается | Реалистичность |
|---|---|---|
| Температура плиток и стали | Одноузловая теплоёмкостная модель на каждый борт (масса именно слоя теплозащиты, не всего корабля) | Инженерно |
| Распределение потока по бортам | Наветренная сторона — по критической точке, подветренный борт — 30 %, теневая сторона — 5 % (конвекция из следа) | Качественно — верный механизм, доли подобраны |
| Прогар теплозащиты | Радиационный баланс по Стефану-Больцману + квадратичное накопление повреждения | Инженерно (излучение) / качественно (критерий прогара) |

### Топливо, ступени, случайности

| Параметр | Как считается | Реалистичность |
|---|---|---|
| MECO / SECO | По остатку топлива, опустошению бака или достижению цели по скорости и высоте | Инженерно |
| Горячее разделение | Бустер держит три центральных двигателя на 40 % вместо полной остановки, пока не зажжётся вторая ступень | Инженерно — реальный приём Starship, не допущение модели |
| Система управления расходованием | Подтравливание клапана горючего с властью 10 % держит соотношение компонентов, чтобы баки не пустели порознь | Инженерно |
| Разброс параметров по прогонам | Гауссов разброс тяги (±0.5 %), удельного импульса (±0.3 %), плотности атмосферы (±4 %), сухой массы и заправки, с воспроизводимым сеедом | Инженерно — методика Монте-Карло, реально применяемая при верификации GN&C |
| Случайный отказ двигателя | Пуассоновский поток отказов, растущий к концу работы ступени, не более чем до двух работающих | Качественно — правдоподобно, не на основе реальной статистики отказов |
| Сброс головного обтекателя | По фиксированной высоте | Качественно / заглушка — не по тепловому потоку, как в реальности |

### Ветер, отработавшая ступень, обломки

| Параметр | Как считается | Реалистичность |
|---|---|---|
| Профиль ветра | Приземный логарифмический слой + струйное течение на 11 км + 3–5 случайных слоёв сдвига, всё гаснет к 60 км | Качественно — верная структура (даёт снос и угол атаки на максимальном напоре), числа климатические, не по конкретной сводке |
| Свободное движение отработавшей ступени | Полный 6-СС полёт (Рунге-Кутта по положению, скорости, кватерниону и угловой скорости) без управления | Инженерно |
| Тепловой режим отработавшей ступени | Три узла (нос/борт/днище) со своими температурами плавления, нагрев по Саттону-Грейвсу | Инженерно |
| Критерий разрушения ступени | Осевой напор > 90 кПа, боковой > 45 кПа, вращение > 3.5 рад/с или прогар узла | Качественно — правдоподобные пороги, не расчёт прочности конструкции |
| Поле обломков | Четыре характерных фрагмента со своими баллистическими коэффициентами, снос ветром, выгорание лёгких по тепловому потоку | Инженерно — тот же приём, что и в реальном анализе зоны падения обломков; число фрагментов и скорость разлёта — оценка |

### Чего нет вообще

- **Возврат и посадка первой ступени** — не моделируется ни для одного носителя: после
  разделения бустер летит неуправляемо и разрушается или падает обломками.
- **Настоящее оптимальное наведение** (PEG, линейно-тангенциальное) — везде, где контур
  замкнутый, это ПИД по орбитальным элементам, а не явное решение задачи оптимального
  управления.
- **Шум навигационных датчиков** — вектор состояния (положение, скорость) в телеметрии
  точный, без модели ГНСС или ИНС; шум есть только на уровне отдельных датчиков двигателя.
- **Дозаправка на орбите, перехват ступеней стартовым сооружением** — не моделируются.

## REST API

Управление прогоном и пультом:

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/api/profiles` | каталог носителей |
| `POST` | `/api/profiles/select` | выбрать носитель на следующий запуск |
| `GET` | `/api/vehicle/layout` | обводы носителя для развёртки |
| `GET`, `POST` | `/api/vehicle/load` | заправка ступеней на следующий пуск |
| `GET` | `/api/control/registry` | реестр управляемых параметров и режимов |
| `GET` | `/api/control/state` | полное состояние для интерфейса |
| `POST` | `/api/control/command` | подать команду |
| `POST` | `/api/control/release` | снять воздействие |
| `GET` | `/api/control/log` | журнал вмешательств |
| `GET` | `/api/control/compare` | сравнение с эталонным прогоном |
| `POST` | `/api/sim/{start,stop,pause,resume,step,reset}` | ход прогона |
| `POST` | `/api/sim/speed?value=5` | скорость модельного времени |
| — | `/api/ws` | поток телеметрии и команд |

Прежний интерфейс телеметрии сохранён:

| Метод | Адрес | Назначение |
|---|---|---|
| `POST` | `/simulation/start`, `/simulation/stop` | запуск и остановка |
| `GET` | `/simulation/data` | полный снимок телеметрии |
| `POST` | `/simulation/separation` | принудительное разделение ступеней |
| `GET` | `/engines` | состояние всех двигателей |
| `PUT` | `/engines/{id}` | тяга и режим одного двигателя |

Все обработчики отвечают `503`, пока прогон не запущен, и читают состояние через
снимок под мьютексом — опрос телеметрии не гоняется с циклом интегрирования.
